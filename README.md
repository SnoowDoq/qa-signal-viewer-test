## Часть 2. Самый критичный сценарий — п. 4 (вместе с 3 и 5)

**Сценарий:** подключиться → нажать «Обновить» → на каждом шаге таблица показывает ровно те данные, которые отправил сервис.

**Почему он:**
- Приложение — часть системы управления, по этим значениям оператор принимает решения. Неверное, «залипшее» или перепутанное между сигналами значение — самый опасный отказ: он **тихий**. Отказ соединения оператор увидит сразу, а неправильную цифру в таблице, которая выглядит правдоподобно, — нет.
- Это основной пользовательский путь. Если он сломан, остальное (обработка ошибок, переподключение) теряет смысл.
- Сценарий покрывает всю цепочку: TCP-приём → парсинг → сопоставление по ID → форматирование → отрисовка в таблице.

## Автотест

Файлы:
- [`tests/test_signal_data_integrity.py`](tests/test_signal_data_integrity.py) — сам тест и проверки (assert)
- [`tests/fake_service.py`](tests/fake_service.py) — управляемый симулятор сервиса (порт 2001, 10 сигналов, синусоида/случайные)
- [`tests/app_driver.py`](tests/app_driver.py) — работа с окном приложения через UI Automation (pywinauto)
- [`tests/conftest.py`](tests/conftest.py) — фикстуры: запуск/остановка сервиса и приложения
- [`demo_app/signal_viewer.py`](demo_app/signal_viewer.py) — демо-заглушка приложения на Qt (PySide6), чтобы тест запускался «из коробки»

### Подход

1. Тест поднимает **свой** симулятор вместо штатного. Он ведёт себя так же, но запоминает каждый отправленный снимок — это эталон, с которым сравнивается таблица. Со штатным симулятором тест не знал бы, какие значения «правильные».
2. Приложение запускается и управляется через UI Automation: Qt 5/6 отдаёт кнопки и `QTableWidget` в UIA, поэтому тест кликает по кнопкам и читает текст ячеек — то же, что видит оператор, без доступа к внутренностям приложения.
3. Проверки (assert):
   - заголовки таблицы соответствуют требованиям;
   - после «Подключиться» приложение запросило данные у сервиса;
   - в таблице ровно 10 строк, без дублей ID;
   - для каждого сигнала имя, значение (с точностью отображения — 3 знака), качество и время совпадают с отправленными;
   - по «Обновить» ушёл новый запрос, и таблица показывает **новый** снимок, а не старый;
   - санити-проверка: данные между снимками действительно изменились.
4. Все расхождения собираются в одно сообщение: при падении сразу видно, какие сигналы и поля не совпали.

Тест проверен и на «сломанных» версиях демо-приложения: искажение значения одного сигнала и отсутствие обновления таблицы по «Обновить». Оба бага пойманы, например: `ID 3: значение -26.675 != -27.675`.

### Допущения

В условии не описаны протокол обмена и формат отображения, поэтому приняты допущения, собранные в одном месте:
- протокол: клиент шлёт `GET\n`, сервис отвечает одной строкой JSON со списком сигналов (`fake_service.py`, docstring). При наличии спецификации меняется только генерация/отправка в симуляторе;
- значение показывается с 3 знаками после запятой, время — `ГГГГ-ММ-ДД ЧЧ:ММ:СС.ммм` в UTC (константы в начале теста);
- заголовок окна — `Signal Viewer`, подписи кнопок — как в условии (`app_driver.py`).

### Запуск

Требования: Windows, Python 3.10+.

```
pip install -r requirements.txt

# на демо-заглушке
pytest

# на реальном приложении (сервис-симулятор тест поднимает сам, штатный должен быть остановлен — порт 2001)
set APP_PATH=C:\path\to\SignalViewer.exe
pytest
```

Под Linux вместо pywinauto используется AT-SPI (например, `dogtail`/`pyatspi`); меняется только `app_driver.py`, симулятор и проверки остаются без изменений.
